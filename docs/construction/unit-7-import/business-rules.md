# Business Rules — Unit 7: Import

| ID | Rule (condition → outcome) | Source |
|----|----------------------------|--------|
| BR-1 | `import_live` with `paths.account` different from `client.account` → `ValidationError`; nothing is read or written. `import_sieve_files` takes no client. | FR-ACCT.4 |
| BR-2 | `import_live` reads live state once with `discover` (read-only, Unit 4 BR-1, BR-2); live filters are addressed by their numbered names, and the report lists the renames. No other `proton` call, and no audit line: import changes local files only. | FR-DISC.1, NFR-SAFE.3 |
| BR-3 | `import_live(name=None)` imports every live filter. `name` given → only that filter; a name no live filter has → `ValidationError` naming it. | FR-DISC.2 |
| BR-4 | `import_sieve_files` imports each source as a filter named by the file name without its `.sieve` suffix (case-insensitive), `enabled` as the local filter's value when it exists, else true. A source without a `.sieve` suffix, an unreadable or non-UTF-8 file → `ValidationError` naming the file. Two sources with one name → `ValidationError` naming both. | FR-DISC.3 |
| BR-5 | Every incoming filter passes `validate_declared` (Unit 3 BR-4, BR-16, BR-17) before anything is written; the first failure raises. Imported scripts are written normalised (Unit 3 BR-12). | FR-DECL.5, FR-DECL.7, FR-DECL.3 |
| BR-6 | Local state is the account's filter files and order file read by `load_local` (Unit 3 BR-19). A missing filters directory or order file is empty local state, not an error; an invalid file propagates its `ValidationError` even with `force`. | FR-DECL.1, FR-DECL.2 |
| BR-7 | An incoming filter whose name has no local filter is `new`. One with a local filter is `changed` when the normalised scripts differ (Unit 4 BR-4) or, for `import_live`, `enabled` differs; otherwise it is left untouched, file included. Names are matched exactly (Unit 4 BR-3). | FR-DISC.2, NFR-REL.1 |
| BR-8 | A local filter no incoming filter names is `preserved`: its file and its place in the order file are never deleted or rewritten. Import never deletes anything. Only `import_live(name=None)` reports them as `preserved`. | FR-DISC.2, RVQ-Q5 |
| BR-9 | The new order of `import_live(name=None)` is the live sequence followed by the local-only names in their local order. For `name` or `import_sieve_files`: the local sequence, then each new name in incoming order. Order entries with no local filter are dropped, and local filters missing from the order file are appended to the local sequence first, sorted by name. | FR-DECL.2, FR-DISC.2 |
| BR-10 | `reordered` is true when the local names, taken in the new order, differ from the local sequence, that is, when an existing order entry would move; names merely inserted do not count. Always false for `name`, `import_sieve_files` and when there is no order file. | FR-DISC.2 |
| BR-11 | Any `changed` filter or `reordered` and `force` false → refused: nothing is written, the report has `refused` true with `new`, `changed`, `reordered` and `preserved`, so the caller prints the local-vs-live differences by name. | FR-DISC.2, NFR-SAFE.1 |
| BR-12 | Not refused → the files are written: each `new` filter, each `changed` filter (only with `force`), and the order file when the new order differs from the local sequence. Nothing is written when none of these exist; the report is `ok` with `written` empty. | FR-DISC.2, NFR-REL.1 |
| BR-13 | A filter is written to the file that already holds it, else to a new file named by `free_filename` (Unit 3 BR-20): `<name>.yaml`, or `<name> (n).yaml` with the lowest `n ≥ 1` when that name is taken by an existing file in the filters directory or by an earlier filter of this import (compared NFC-normalised and case-folded). The filter's `name` inside the file is unchanged, and no existing file is replaced by another filter's content. | FR-DECL.4 |
| BR-14 | Each file is written by temp file and `os.replace` in its directory, creating the directories; filter files first in incoming order, the order file last. An `OSError` → `SieveAsCodeError` naming the path and the system message; files already written stay and a rerun completes the rest (BR-7, BR-12). | NFR-REL.1 |
| BR-15 | After a successful import, `load_declared` accepts the account's files, and for `import_live(name=None)` the declared state equals live state (names, normalised scripts, `enabled`, order) apart from `preserved` filters, so `plan` reports none of the imported filters. | US-1.1, US-1.3 |
| BR-16 | Errors and the report carry names and paths only, never script text. | NFR-SAFE.2 |
