# Business Rules — Unit 8: Retroactive run

| ID | Rule (condition → outcome) | Source |
|----|----------------------------|--------|
| BR-1 | Any public function with `paths.account` different from `client.account`, or a client with no fingerprint (not from `connect`) → `ValidationError`; nothing is read, written or audited. | FR-ACCT.4 |
| BR-2 | `preview` and `run` resolve `name` among the live filters by `discover` (numbered names, Unit 4 BR-2), matched exactly. An unknown name, or a disabled filter, → `ValidationError` naming it (a disabled one: enable it first). `audit_all` covers the enabled filters only. | FR-RETRO.1, FR-RETRO.5 |
| BR-3 | Preview reads are `discover`, `list_folders`, `list_labels`, one `list_messages()` and the recipient searches of BR-10: list and get verbs only. A `ClientError` propagates and nothing is written. A message row without `id`, `subject`, `from_name`, `from_address` (strings), `time`, `unread` (integers) and `labels` (list of strings) → `ClientError` as for any unexpected output (Unit 2 BR-11). | FR-RETRO.1, FR-PLAN.6 |
| BR-4 | A message labelled `4` (Spam) is never evaluated or listed; it is counted in `spam_excluded`. Every other message in the listing, Trash included, is evaluated. | FR-RETRO.1, RVQ-Q7 |
| BR-5 | A message's location is the first of the system ids `3` Trash, `6` Archive, `0` Inbox, `7` Sent, `8` Drafts found in its labels, else the path of the custom folder whose id is among its labels, else `unknown`. Its date is the UTC date of `time` (epoch seconds). | FR-RETRO.1 |
| BR-6 | `compile_script` accepts only this subset, anything else → `UnsupportedSieve` naming the construct and line, never quoting the script. Commands: `require` (any list; extension gating stays with Unit 3 BR-17), `if`/`elsif`/`else`, `stop`, `fileinto` with a literal string (no `:copy`), `addflag`/`setflag`/`removeflag`, `expire "day" "N"`. Tests: `allof`, `anyof`, `not`, `true`, `false`, `address` and `header` on `from`, `to` or `subject` with `:is`, `:contains` or `:matches` and the default comparator. No `:regex`, variables, `include`, `vacation`, `reject`, `keep`, `size`, `exists` or other header names. | FR-RETRO.2 |
| BR-7 | Matching is case-insensitive (`i;ascii-casemap`); `:matches` treats `*` and `?` as wildcards with `\` escaping them; a test with several keys matches when any key matches. `address` on `from` tests `from_address` as `:all` (default), `:localpart` or `:domain`; `header` on `from` tests `from_name <from_address>` (the address alone when the name is empty); on `subject` tests `subject`. A message with an empty address matches no `address` test. | FR-RETRO.2 |
| BR-8 | `evaluate` runs the filter's script alone, top to bottom: the first true branch of an `if` chain runs, `stop` ends. It returns the `fileinto` targets in order (duplicates case-folded once), the final flag set (flags only from BR-12, `setflag` replaces, `removeflag` removes) and the last `expire` days. Other filters of the account are not considered, as `filters apply NAME` acts on that filter only. | FR-RETRO.1, FR-RETRO.2 |
| BR-9 | Every `fileinto` target must resolve case-insensitively, a custom folder path before a label name: `Inbox`, `Archive`, `Trash`, `Spam` are system folders, a path in `list_folders` a folder, a name in `list_labels` a label. An unresolved target → the filter is not previewable (BR-14), naming the target. | FR-RETRO.2 |
| BR-10 | The listing carries no recipients, so a `to` test (`:is` or `:contains` with `:all`, on `address` or `header`) is answered by `list_messages(to=KEY)` per distinct key: a message matches the key when its id is in that result. The preview is `approximate` (Proton's recipient search decides). A `to` test with `:matches`, `:localpart` or `:domain`, or more than 10 distinct keys in one filter → not previewable. | FR-RETRO.2 |
| BR-11 | Compilation, the BR-9 check and the BR-10 limits are done before any message is evaluated. A filter failing any of them is not previewable: `previewable` false, `reason` naming the construct or target, no entries, no guessed list. | FR-RETRO.2 |
| BR-12 | The only flags understood are `\Seen` (read) and `\Flagged` (starred), case-insensitive; any other flag → `UnsupportedSieve`. A final set holding `\Seen` yields the action `read`, `\Flagged` yields `star`. Absence of a flag never yields an action. | FR-RETRO.2 |
| BR-13 | `expire "day" "N"` with a positive integer N yields the action `expire N day`; any other form → `UnsupportedSieve`. Expiry cannot be observed in the listing, so it is shown on a listed message but never makes a message count. | FR-RETRO.2 |
| BR-14 | A previewable message is listed only when an action would change it: a `fileinto` folder whose id differs from its location (BR-5); a label whose id is not in its labels; `read` when `unread` is 1; `star` when label `10` is absent. Each entry carries id, date, sender (`from_address`), subject, location, and the actions (`move: PATH`, `label: NAME`, `read`, `star`, `expire N day`). Entries are ordered newest first, ties by id. | FR-RETRO.1 |
| BR-15 | `declared_differs` is true when `load_local` (Unit 3 BR-19) holds a filter of that name whose normalised script or `enabled` differs from live (Unit 4 BR-4); the preview then warns that the run uses the live script. It never blocks. An invalid local file propagates its `ValidationError`. | FR-RETRO.3, RVQ-Q23 |
| BR-16 | `preview`, `status` and `audit_all` change nothing in Proton and write no snapshot. Only `audit_all` appends an audit line (BR-28). | NFR-SAFE.1, FR-RETRO.5 |
| BR-17 | `run` computes the preview itself (BR-2 to BR-15), then applies the gate. A previewable filter with no entries → nothing to do: no snapshot, no `proton` write, no audit line; the report is `ok` and `started` false. | NFR-REL.1 |
| BR-18 | The gate passes only when `confirmed_name` equals the filter name exactly (case-sensitive) and `reason` is not blank. Otherwise nothing is written and no snapshot is taken; the report is `refused` with the preview, and one `check` audit line is appended: outcome `refused`, detail `command`, `name`; a failing audit write raises `SieveAsCodeError` (nothing was started). | FR-RETRO.3, NFR-SAFE.1 |
| BR-19 | A confirmed run of a not previewable filter proceeds without a snapshot (RVQ-Q8); the report says so (`snapshot` None). | FR-RETRO.2 |
| BR-20 | A confirmed run of a previewable filter writes the snapshot before the `proton` call. A snapshot failure raises `BackupError` and nothing is started or audited. | FR-RETRO.4 |
| BR-21 | A snapshot is a JSON object with exactly `format` (1), `created` (UTC, ISO 8601, `Z`), `account`, `fingerprint`, `filter` (name), `script_sha256` (of the normalised live script), `messages` (the ids of the entries, sorted) and `checksum`, written like a backup (Unit 5 BR-4 to BR-6) as `<YYYYMMDDTHHMMSSffffffZ>.json` in `paths.retroactive_dir`. It holds no sender, subject, script or reason. | FR-RETRO.4, NFR-SAFE.2 |
| BR-22 | The run is one `apply_retroactively(live_id)` (Unit 2 BR-21); it is not cancellable and not polled, so `started` means Proton accepted the command, not that mail was moved. A `ClientError` → the report has `failed` holding its message (first line, at most 200 characters); the snapshot stays. | FR-RETRO.3, CON-2 |
| BR-23 | After the call one `write` audit line is appended: outcome `started` or `failed`, detail `command` (`apply-retroactive`), `name`, `reason`, `messages` (entry count, None when not previewable) and, on failure, `exit_code`. The reason is the only free text ever audited. A failing audit write never replaces the report: it is kept with `audit_error`. | FR-RETRO.3, NFR-SAFE.2, NFR-SAFE.3 |
| BR-24 | After a new snapshot is written, every snapshot file in `paths.retroactive_dir` (names matching BR-21, time from the name) older than 10 days is deleted, never the new one. If any was removed, one `write` audit line: outcome `prune`, detail `removed`, `kept`. A failed removal is reported in `prune_error` and does not fail the run. | FR-RETRO.4 |
| BR-25 | `RetroReport.ok` is true when the run was not refused, `failed` is None and `audit_error` is None. | FR-RETRO.3 |
| BR-26 | `status(ref)` resolves and verifies the snapshot as Unit 5 BR-9 and BR-10 do, in `paths.retroactive_dir`, for the client's fingerprint (`ref` None is the latest); a fault → `BackupError`. It then previews the snapshot's filter (BR-2; a missing or disabled filter → `ValidationError`; not previewable → `ValidationError` naming the reason). | FR-RETRO.4 |
| BR-27 | With S the snapshot's ids, P the current entries' ids and L the ids now listed: **pending** is S ∩ P; **done** is S ∩ L not in P; **unexpected** is P not in S (reason `new`) and S not in L (reason `gone`). `script_changed` is true when the current script's hash differs from `script_sha256`. The report carries the pending entries. | FR-RETRO.4 |
| BR-28 | `audit_all` evaluates every enabled filter over one message listing, sharing the recipient searches. Per filter: the number of entries, or None and the reason when not previewable, plus a note `approximate` (BR-10). It appends one `check` audit line: outcome `audited`, detail `filters`, `not_previewable`, `approximate` (counts). | FR-RETRO.5, NFR-SAFE.3 |
| BR-29 | Audit lines, snapshots and errors carry names, counts, ids and hashes only; never a script, a sender, a subject or a message address. | NFR-SAFE.2 |
