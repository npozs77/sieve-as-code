# Business Rules — Unit 9: CLI and public API

| ID | Rule (condition → outcome) | Source |
|----|----------------------------|--------|
| BR-1 | `sieve_as_code.__all__` is the whole public surface: the 14 functions, the result and data types, `SieveAsCodeError`, `ValidationError`, `ClientError`, `BackupError` and `__version__`, as listed in the logic model. A name in `__all__` that does not resolve, or a public-looking name outside it, fails the surface test. Every other module is underscore-prefixed except `cli`. | FR-CLI.2, RVQ-Q29 |
| BR-2 | Every public function takes its subject positionally and every other parameter by keyword. Each one that reads an account takes `account: str | None = None`, resolves it with `resolve_account` and `account_paths`, and calls `connect` only when the internal function takes a client; `import_sieve_files`, `backup_diff`, `load_declared` and `validate_declared` do not connect. A wrapper adds no logic beyond this and BR-3. | FR-CLI.2, FR-ACCT.1 |
| BR-3 | `confirmed` and `allow_delete` and `force` default to `False`: a call that names no confirmation never writes to Proton or overwrites a declared file. | NFR-SAFE.1 |
| BR-4 | Public results are the internal frozen dataclasses. The one change is `Snapshot`, which gains `pruned: tuple[str, ...] = ()` and `prune_error: str \| None = None`. `validate_declared(declared)` takes a `FilterSet`; `load_declared` returns one. | FR-CLI.2, RVQ-Q29 |
| BR-5 | `backup(keep_days=None, keep_last=None)` writes the snapshot, then prunes with each limit taken from the argument when given, else from `retention()`. Both unset → no prune call. An argument below 1 or not an integer → `ValidationError` before any Proton call. A prune `BackupError` is not raised: the snapshot is returned with `prune_error` and the names removed in `pruned`. The `apply` and `restore` snapshots never prune. | FR-BAK.6, RVQ-Q30 |
| BR-6 | `main` returns 0 when the command succeeded (its report `ok`, or a read command that finished); 1 when it ran but was refused, failed or left a diff (report not `ok`), or raised a `SieveAsCodeError` other than `ValidationError`; 2 for `ValidationError` and for usage errors; 130 on `KeyboardInterrupt`. An error prints `error: MESSAGE` on stderr, no traceback. | HLD errors, NFR-OPS.1 |
| BR-7 | A diff is output, not failure: `plan` with drift, `backup-diff` with differences, `retroactive-status` with pending or unexpected messages and `retroactive-audit` exit 0. `restore` whose remaining diff is not empty exits 1 (`RestoreReport.ok`). | FR-PLAN.4, FR-BAK.4 |
| BR-8 | `apply` and `restore` without `--yes` call the library with `confirmed=False`; the refused report's plan is printed, followed by `nothing written; re-run with --yes`, and the exit is 1. `--allow-delete` exists on `apply` only. | FR-APPLY.1, FR-BAK.4, NFR-SAFE.1 |
| BR-9 | `apply-retroactive NAME` prints the preview, then: previewable with no entries → `nothing to do`, exit 0, no prompt. Otherwise it prompts for the filter name and a reason on stdin, naming the account, its fingerprint and that the run cannot be cancelled, and passes both answers to `apply_retroactive`. End of input counts as an empty answer. A refused report prints `not confirmed; nothing changed` and exits 1. The command has no `--yes`. | FR-RETRO.1, FR-RETRO.3, NFR-SAFE.1 |
| BR-10 | Every command's output begins with `account: NAME (fingerprint F)`, printed after the command's connection check, with `F` read from `paths.account_marker`; with no marker yet (`import --sieve` on a new account) it prints `account: NAME`. The confirmation prompt of BR-9 repeats both. | FR-ACCT.3 |
| BR-11 | Output carries only what the result types hold. Only `discover` prints script text. Preview entries show date, sender, subject, location and actions (FR-RETRO.1); nothing the CLI prints reaches the audit log. | NFR-SAFE.2 |
| BR-12 | `discover` prints, per `render` file, a `# FILE` line and the file text, the order file last, then one `renamed: A -> B` line per rename. It writes nothing. | FR-DISC.1 |
| BR-13 | `import [NAME] [--force]` imports live filters; `import --sieve FILE...` imports `.sieve` files; `NAME` with `--sieve` is a usage error. A refused import prints the `changed` names and `re-run with --force`, exit 1. | FR-DISC.2, FR-DISC.3 |
| BR-14 | `--account NAME` is accepted by every subcommand; unset it falls to the library (`SIEVE_AS_CODE_ACCOUNT`, else `default`). `--keep-days` and `--keep-last` accept whole numbers of 1 or more (else usage error), on `backup` only. No command → help and exit 2; `--help` and `--version` exit 0. | FR-ACCT.1, FR-CLI.1, FR-BAK.6 |
| BR-15 | `main(argv=None)` returns the exit code and never raises `SystemExit`: a usage error or `--help` from `argparse` is returned as its code. The console script `sieve-as-code = sieve_as_code.cli:main` resolves to it. | FR-CLI.1 |
| BR-16 | `__version__` equals the `version` in `pyproject.toml`. | FR-CLI.2 |
| BR-17 | The rename changes module names and imports only: every earlier test passes with import paths changed and nothing else. | RVQ-Q29 |
| BR-18 | `tests/live/` is skipped unless `SIEVE_AS_CODE_LIVE_TEST=1`; it needs `SIEVE_AS_CODE_ACCOUNT` set and refuses to start when filters cannot be listed. It creates, changes and deletes only filters named `sieve-as-code-test-*`; every test deletes what it created in a `finally` block. The restore test also needs an account with no filter outside that prefix, else it skips with the reason. | NFR-TEST.2, RVQ-Q19 |
| BR-19 | The README states the tested `proton-cli` range (`TESTED_MINIMUM`), that a rename is a delete plus a create, the public API list, and the semver and provisional-until-1.0 policy; its status and usage sections describe the working CLI. `CHANGELOG.md` has an `Unreleased` section listing what Units 1–9 add. | NFR-REL.3, FR-DECL.4, FR-CLI.2 |
